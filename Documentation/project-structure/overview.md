# Project Structure Overview

## Scope
- This documentation is based only on the executable project code and project assets outside the existing `Documentation/` tree.
- Existing files under `Documentation/` were intentionally excluded from the structure analysis.

## Top-Level Folders
- `backend/`
  - Django API and business logic.
  - Contains project configuration in `backend/config/` and domain apps in `backend/apps/`.
- `frontend-mobile/`
  - Expo / React Native mobile client.
  - Contains app screens, navigation, API clients, session handling, and Android native scaffolding.
- `web-admin/`
  - Lightweight React + Vite web surface.
  - Currently acts as a static landing/admin shell rather than a full operational console.
- `implementation plan/`
  - Delivery planning documents for backend, mobile, media, testing, and operations.
- `Proposed design/`
  - Visual references, HTML mockups, and design explorations used to guide implementation.
- `.vscode/`
  - Editor-specific workspace settings.

## Root Files
- `README.md`
  - Basic repository onboarding.
- `Design PLAN.md`
  - Product/design planning document used as a reference during implementation.
- `firebase.json`, `.firebaserc`
  - Firebase hosting/deployment configuration.
- `db.sqlite3`
  - Local development database artifact at the repository root.

## System Separation
- Backend
  - Implemented in Django REST Framework under `backend/`.
  - Domain-driven app split: accounts, regions, rates, directory, news, ads, reverse search, services, and admin operations.
- Frontend
  - `frontend-mobile/` is the main user-facing client for members, guests, admins, and operational workflows.
  - `web-admin/` is a separate web surface for landing/admin presentation.
- Shared Modules / Utilities
  - There is no standalone shared package across backend and frontend.
  - Backend serializers and models define server contracts.
  - `frontend-mobile/src/types/api.ts` mirrors those contracts for mobile consumption.
  - Media upload helpers are centralized in `backend/config/storage.py`.

## Backend Folder Map
- `backend/config/`
  - Django settings, URL registration, ASGI/WSGI bootstrap, and mock upload utilities.
- `backend/apps/`
  - Domain apps grouped by business capability.
  - `accounts/`: authentication, profile, role scope, notification preferences.
  - `regions/`: state -> association -> district operational unit -> unit hierarchy.
  - `rates/`: bullion dashboard and comparison APIs.
  - `directory/`: company tiers, market feed, catalog, products, enquiries, market analytics.
  - `news/`: news publishing, targeting, meetings, approvals, and visibility rules.
  - `ads/`: advertisement delivery, upload sessions, impression/click tracking.
  - `reverse_search/`: protected reverse-design request workflow with attachments.
  - `services_app/`: compliance dashboard and service metrics.
  - `admin_ops/`: hierarchy administration, admin overview, seed utilities.
- `backend/media/`
  - Local media files for development, currently used by the news system.

## Frontend Folder Map
- `frontend-mobile/src/api/`
  - Mobile-side HTTP wrappers for backend APIs.
- `frontend-mobile/src/navigation/`
  - Stack and tab navigation wiring.
- `frontend-mobile/src/screens/`
  - Screen modules grouped by feature area: auth, dashboard, directory, news, profile, reverse search, services, splash.
- `frontend-mobile/src/session/`
  - Session bootstrap and authenticated user state.
- `frontend-mobile/src/storage/`
  - AsyncStorage persistence for tokens and guest sessions.
- `frontend-mobile/src/components/`
  - Reusable UI primitives shared across screens.
- `frontend-mobile/src/theme/`
  - Design tokens and app-wide styling constants.
- `frontend-mobile/src/types/`
  - Typed API contracts used across the mobile app.
- `frontend-mobile/android/`
  - Native Android project generated by Expo.
- `frontend-mobile/References/`
  - Static UI/design references, not runtime code.
- `web-admin/src/`
  - Small React app with an `App` shell, landing page, admin dashboard page, and shared stylesheet.

## How To Navigate The Repo Quickly
- Start in `backend/config/urls.py` to see every exposed API surface.
- Move to `backend/apps/<domain>/views.py` for request handling.
- Use the matching `models.py`, `serializers.py`, and `services.py` files to understand persistence, payload shape, and business rules.
- In mobile, start with `frontend-mobile/src/navigation/RootNavigator.tsx` to see the complete screen map.
- Use `frontend-mobile/src/api/` plus `frontend-mobile/src/types/api.ts` to connect mobile screens to backend endpoints.
